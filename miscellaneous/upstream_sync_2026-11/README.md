# 원본(OpenEPaperLink) 동기화 기록 — 2026-11

이 포크가 갈라진 시점(`f1b5c89`, 2026-03-30) 이후 원본에 쌓인 변경을 비교·분석하고, 이 포크에 필요한 것만 골라 이식한 기록입니다.
다음 동기화 때 같은 분석을 반복하지 않도록 판단 근거와 주의점을 함께 남깁니다.

- 비교 대상: 원본 `master` `1ec6ae2`(2026-11-07)까지 **243 커밋**. 펌웨어 관련은 187개이고, 나머지 56개는 라디오 태그용 tagtype JSON, 태그 펌웨어, 문서, 측정 도구입니다.
- 이 포크의 사용 환경:
  - BLE 기기만 사용: Wolink 2.13/3.5/7.5" BWRY, GICisky 2.9" BWRY, Nemonic MIP-201 라벨 프린터, ATC BLE.
  - 빌드는 `ESP32_S3_16_8_YELLOW_AP`, `BLE_ONLY_AP` 두 개.
  - AP의 Repo 설정은 이 포크입니다.
- 결론: 전체 머지는 하지 않습니다. BLE(포크는 NimBLE, 원본은 Bluedroid), C6 시리얼(원본은 프로토콜 v2), contentmanager(원본은 파일 분할)가 전면 충돌합니다. 대신 원본 2026-10 안정화 수정을 커밋 단위로 가져오고, 포크 고유 버그를 함께 고쳤습니다.

## 3. 하드웨어 점검표
CI 아티팩트(Actions 실행 → Artifacts)로 플래시해서 확인합니다.
- `firmware.bin`은 OTA 업로드용으로 설정이 유지됩니다.
- `merged-firmware.bin`은 USB로 0x0에 쓰며 설정이 초기화됩니다.

Yellow AP부터 확인합니다.
1. **부팅**:
   - `/tagtypes`에 버전 100 파일이 있음.
   - 업데이트 탭 repo가 eseungho.
   - 새로고침 후 Nemonic UI가 반영됨.
2. **Wolink**: 2.13/3.5/7.5"에 흑백 전용 이미지와 컬러 이미지가 모두 표시됨.
3. **C6 분리**: 1시간 동안 BLE MAC에 대한 SDA/CXD 로그와 빨간 "xfer timeout"이 없음.
4. **교체 경쟁**: 7.5"에 1분 시계 콘텐츠를 걸어도 미리보기와 화면이 일치하고 대기 상태가 남지 않음.
5. **공정성**: 대기 중인 기기 하나의 전원을 꺼도 다른 기기는 계속 갱신됨. 꺼진 기기는 약 3분 뒤 포기되고 `.pending`이 사라짐.
6. **Nemonic**: 라벨마다 정확히 한 번 인쇄됨. 프린터를 끈 상태에서는 맨 앞 작업만 삭제됨.
7. **라디오**:
   - 0x001f 매니페스트 재플래시 성공.
   - 0024는 거부되고 재부팅 없이 복귀.
   - C6를 분리해도 BLE 기기는 계속 갱신됨.
8. **Wi-Fi·기타**:
   - 공유기를 2분 꺼도 설정 AP가 열리지 않음.
   - `/coredump`는 평소 404.
   - 여러 번 재부팅해도 TFT assert가 없음.
9. **7일 이상 소크**: Health 라인이 평탄하고(내부 RAM 감소 없음), 야간 재부팅 외에는 재시작이 없음.

## 4. 다음 동기화 때 주의
- **cherry-pick 옵션**: `git cherry-pick -x -X renormalize -X ignore-space-at-eol <sha>`. 원본이 일부 파일을 CRLF로 바꿨기 때문입니다. 적용 후 CR이 남았는지 확인합니다(CI `web-assets` 잡도 검사함).
- **웹 파일**: 원본의 `data/www/*.gz` 변경분은 받지 말고 `python gzip_wwwfiles.py`로 재생성합니다.
- **BLE 커밋**: 원본은 Bluedroid이므로 cherry-pick이 불가합니다. 로직만 `ble_writer.cpp`·`ble_filter.cpp`(NimBLE)에 옮깁니다.
- **C6 펌웨어**: 원본 `binaries/ESP32-C6`를 그대로 복사하지 않습니다(0x0023 이상은 프로토콜 v2 전용).
- **태그 ID**: 포크 고유 ID를 원본이 다시 쓰는지 확인합니다. 원본이 아직 쓰지 않는 범위는 0xA0~0xAF입니다.
- **태그 릴리스**: 태그를 푸시하면 release.yml이 릴리스를 게시하고 AP의 "Update now!"가 바로 제안합니다. 하드웨어 확인 뒤에 태그를 답니다.
